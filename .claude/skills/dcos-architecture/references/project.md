## WBS Templates (Master Libraries) — mapped 2026-11-05
- **Table** `wbs_templates` (15 local): header columns (`template_name`, `template_category`, `building_types`, `kit_code` → `plan_act_kits`, `default_level_template_id`) and `content` jsonb `{schema, sections{nodes,tasks}, floor_blocks{basement,ground,typical,roof}{nodes,tasks}, building_anchor_key}`. Nodes: `key` / `parent_key` (dotted), `node_type` (phase, task_group…), `discipline`, `cost_code`. Tasks: `key`, `node_key`, `task_name`, `duration_days`, `discipline`, `is_milestone`, `predecessors[{key, scope sections|same|prev_floor, type, lag}]`, **`master_code`** (= `plan_act_masters.code`, version-agnostic). `wbs_template_nodes` is legacy and unused.
- **Breakdown:** phase (01 Design, 02 Procurement, 03 Construction, 04 T&C / Handover) > building anchor > level-type floor block > discipline > task. Location axis only; the Work Library (CSI > activity) defines the work. They link through `master_code` and nothing else ("link, don't merge", 2026-11-05).
- **Apply:** `lib/project/wbs/wbs-template.ts` expands per building → `apply_wbs_template(project, template, payload, levels)` → `import_master_wbs(..., 'merge')`, then stamps level types and sets `wbs_tasks.activity_master_id` from `master_code` (active version, else newest) where null. Generate and the BOQ programme match tasks by `activity_master_id`, so an unlinked template task can be duplicated.
- **Rule** (`lib/project/wbs/template-activity-rules.ts`): construction tasks (the Construction phase of the fixed sections, found by name / `C-` cost code, and every floor block) must link; non-construction phases, milestones and `FREE_DISCIPLINES` (Design, Procurement, Documentation, Shop Drawings, BIM, QA/QC, Handover, Commissioning) may stay free. The editor (`components/administration/wbs-template-editor.tsx`) shows the coverage chip, a jump list of tasks to link, row badges, and warns (does not block) on save.
