## Known so far (from other maps)
- No hub card yet. BIM models and takeoff; promotes BIM quantities to QS BOQ and feeds Planning quantities (see integration-map.md).
- **Schedules (2026-10-30):** all 14 Arc / Str / MEP schedules use `components/design/generic-schedule.tsx` (`arc-schedules.tsx` re-exports it): scoped to the selected project, `project_id` set on insert (before this every insert used a random uuid and failed the `projects` FK, so the tables were empty), `options` for CHECK-constrained columns, optional `link` picker to a library item.
- **Links (`20261030164500`):** `design_mep_commissioning.tc_item_id` → `plan_act_tc_items`, `design_mep_material_submittal.resource_id` → `dwl_resources` (QS material), `design_coordination_log.coordination_item_id` → `plan_act_coordination_items`. Pickers use `lib/planning/public.ts` (`searchTcItems`, `searchMaterials`, `searchCoordinationItems`, `getChipOptionsByIds`). The Planning Requirements Tracker counts commissioning (passed/closed = done) and coordination log entries (resolved/closed = done).
- **RLS:** all 19 `design_*` tables are `is_project_member(project_id)` for select / insert / update / delete (`20261030164500` for three, `20261030173000` for the other 16; before that they were `using (true)` for any authenticated user). Design has no `role_permissions` rows, so there is no per-role check yet. `design_arc_material_approval` is not linked to QS materials yet.
- **Project scope:** every Design screen (schedules, drawings, RFIs, room data, review comments, markup drawing list, Design hub counts) reads and writes the selected project (`useProject`); the queries in `lib/design/design-queries.ts` take `projectId`. Allowed values of the CHECK constraints live in `components/design/schedule-options.ts`; a blank field is left out of a new row so the column default applies.
