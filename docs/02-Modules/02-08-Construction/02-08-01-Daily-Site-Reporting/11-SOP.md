# DCOS — Daily Reporting Module
## 11 — Standard Operating Procedure

| Field | Detail |
|---|---|
| Document Code | DCOS-DR-SOP-001 |
| Version | R1 (Phase 1A) |
| Module | 10-01 — Daily Reporting |
| Status | Issued for Review |
| Applies to | Projects where Daily Reporting is switched on |

---

## 1. Purpose

To make each day's site record complete, attributable, reviewed and usable as a contemporaneous record.

## 2. Responsibilities

| Role | Responsible for |
|---|---|
| Reporter (subcontractor supervisor, in-house supervisor) | One report for their unit every working day by the deadline; answering returns and questions within 24 hours |
| Unit lead | Making sure the unit reports when the usual reporter is absent |
| Project Manager (approver) | Reviewing each report within 12 hours; publishing the daily summary; excusing missing reports with a reason |
| Alternate approver | Acting for the PM inside the dates set |
| System administrator | Setting approvers; switching the page on; global rule defaults |
| Project Director | Acting on escalations; reading the published summary |
| QS | Using verified quantities as measurement support only |

## 3. Daily timetable (defaults)

| Time | Event |
|---|---|
| 16:00 | Reminder to reporters who have not submitted |
| 18:00 | Deadline. Unsubmitted units are recorded as missing; reporters notified |
| 09:00 next day | Missing reports escalated to the approver. End of the late window: later reports are also flagged Backdated |
| Within 12 h of submission | Approver decides, or is reminded |
| After 24 h | Unreviewed reports escalated to management |
| 09:00 second day | Missing reports escalated to management |

## 4. Procedure: reporter

1. Open Daily Reporting, choose the date, **Start report**.
2. Record what happened. Do not round up. Enter cumulative progress and today's quantity for each activity.
3. Take photos inside the form for each activity. Photos sent by chat are not evidence.
4. Record every delay when it happens, with hours lost. Tick **Notice required** if the cause is the employer, design information, access or an authority.
5. Record instructions received, including verbal ones, with who gave them.
6. Record any incident. HSE is notified at once.
7. If no work was done, submit **No work today** with the reason. Do not stay silent.
8. Read the review screen. Fix errors. Warnings go to the PM; add a remark where one explains the figure.
9. Submit and keep the report number.
10. If the report comes back: open it, read the PM's reason, correct only the returned items, reply briefly, resubmit.

## 5. Procedure: approver

1. Open **Review**. Start with flagged reports.
2. For each report check: findings; photos against the claimed activity; quantity against the area and crew; delays and their causes.
3. Decide:
   - **Approve** if it is a fair record.
   - **Adjust** a quantity you do not accept: enter the verified quantity and say why. The reported figure stays on record.
   - **Classify** each delay. The proposed class is a starting point; the contract decides.
   - **Request information** when a question is enough.
   - **Return** the specific items that are wrong, with a reason for each. Do not return a whole report for one line.
4. Never approve a report you submitted yourself; ask the alternate approver.
5. At the day's cut-off open **Daily summary**, read the coverage line, add a short narrative, **Publish**.
6. If approvals or amendments arrive later, publish the next revision.
7. Review **Missing reports** each morning. Excuse only with a real reason (site closed, unit not yet mobilised).

## 6. Amendments

An approved report is amended, never edited. The person amending gives the reason; a different approver approves it. Use an amendment for a factual error found later, not to renegotiate a verified quantity.

## 7. Controls

| Control | Why |
|---|---|
| Versions cannot be changed or deleted | The record must stand up in a dispute |
| Reported and verified quantities are separate | A claim is not a measurement |
| Verified is not certified | Payment is certified in the IPC process only |
| Planning is updated on approval only | The schedule must not move on unverified figures |
| Submitter cannot approve | Independent check |
| Approvers are set by a system administrator | No self-appointment |
| The unit never sees internal findings | Avoids coaching the reporter around the checks |
| Evidence is scanned, hashed and time-stamped by the server | Integrity of the evidence |

## 8. Delay notices

A delay flagged **Notice required** alerts the approver and QS at submission. This is early warning of a possible contractual notice; it is not the notice. The party responsible for contract administration must check the contract's time bar and issue the notice in the contractual form. When the report is approved, QS and management are notified again and the delay enters the delay register with the approver's classification.

## 9. Absence

- **Reporter absent:** the unit lead or another reporter of the unit submits. If the unit has only one reporter, the PM asks the administrator to add another.
- **PM absent:** a system administrator sets an alternate approver with an end date before the absence starts.

## 10. Records and retention

Reports, versions, evidence and the audit log are kept for the project duration, the defects liability period and five years after. They are not removed in routine archiving.

## 11. Non-compliance

| Situation | Action |
|---|---|
| Unit missing two consecutive days | PM raises it with the subcontractor's manager; record under the subcontract's performance provisions |
| Repeated returns for the same reason | PM briefs the reporter; consider making photos mandatory (block submission) for that unit |
| Photos reused or unrelated | Return the report; record the event; escalate if repeated |
| Report approved without review | Project Director reviews approval times and return rates monthly |
