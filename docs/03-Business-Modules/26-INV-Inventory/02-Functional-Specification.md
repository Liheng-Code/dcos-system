# Inventory / Stock Module — Functional Specification
**Document Code:** DCOS-FS-26-001 | **Version:** R0 | **Date:** June 2026
**Module Code:** INV | **Domain:** Supply Chain | **Phase:** 3
**Status:** Draft — Pending Human Approval

---

## 1. Features

### F1: Item Master Catalogue
**Description:** A centralised catalogue of all material items used across the organisation, with unit of measure, category, default cost code, and re-order parameters.

**Business Rules:**
- BR-F1-01: Each item has a unique Item Code generated by the system (prefix + sequence, e.g. `MAT-00001`).
- BR-F1-02: Items are classified by category (Structural, Civil, MEP, Finishes, Consumables, Others — admin-configurable).
- BR-F1-03: Unit of measure (UoM) is set at item level and cannot be overridden per transaction (e.g., rebar is always in kg or tonne).
- BR-F1-04: Each item has optional fields: min stock level, max stock level, reorder point, lead time (days).
- BR-F1-05: Items can be deactivated (soft-delete) — deactivated items cannot be used in new transactions but retain historical records.
- BR-F1-06: Item master is shared across projects within a tenant; stock quantities are per-project per-store.

---

### F2: Store Master
**Description:** Each project can have one or more physical stores (main store, sub-store, temporary site store).

**Business Rules:**
- BR-F2-01: Each store belongs to exactly one project and one tenant.
- BR-F2-02: A store has a unique Store Code, name, location description, and responsible Storekeeper.
- BR-F2-03: Stores can be designated as Main Store or Sub-Store — inter-store transfers between them are tracked.
- BR-F2-04: A store can be set to Active or Closed. Closed stores cannot receive new transactions.

---

### F3: Goods Received Note (GRN)
**Description:** Records the physical receipt of materials at the site store, linked to a Procurement PO.

**Business Rules:**
- BR-F3-01: Every GRN must reference a valid, approved PO from the Procurement module.
- BR-F3-02: GRN captures: delivery note number (supplier), vehicle plate, driver name, received by (Storekeeper), received date and time, line items with quantities and condition.
- BR-F3-03: Received quantity can be less than or equal to PO quantity (partial delivery is valid). Received quantity cannot exceed outstanding PO balance.
- BR-F3-04: Upon GRN creation, stock is added to inventory with status: Available (if no inspection required) or Under Inspection (if QAQC inspection is required per item or PO flag).
- BR-F3-05: If inspection is required, the system notifies the QAQC Engineer. Materials remain in quarantine (status = Under Inspection) until QAQC approves or rejects.
- BR-F3-06: QAQC rejection creates a Return-to-Supplier record and does not add stock to Available balance.
- BR-F3-07: GRN is immutable once confirmed. Corrections require a Credit GRN (negative adjustment linked to original).
- BR-F3-08: GRN triggers a cost commitment in the Cost Control module.
- BR-F3-09: Batch number and test certificate reference are optional fields on GRN line items.

---

### F4: Material Requisition (Issue)
**Description:** Site engineers request materials from the store for use on specific tasks and WBS nodes.

**Business Rules:**
- BR-F4-01: Material Requisition (MR) must reference a valid project, WBS node, task, and cost code.
- BR-F4-02: MR is raised by the Site Engineer/Supervisor and must be approved by the same level or above before the Storekeeper processes the issue.
- BR-F4-03: The system checks available stock before approval. If insufficient stock, the MR is flagged with a warning but not blocked at request stage (blocked at approval stage unless override is permitted by role).
- BR-F4-04: Storekeeper issues the materials physically and confirms issue in the system. Issue quantity can be less than or equal to the approved MR quantity (partial issue is valid).
- BR-F4-05: Upon issue confirmation, stock balance is reduced and a cost transaction is posted to the Cost Control module (WBS + cost code).
- BR-F4-06: MR cannot be issued from materials in quarantine (Under Inspection status).
- BR-F4-07: MR number is system-generated: `MR-[ProjectCode]-[Sequence]`.

---

### F5: Material Return to Store
**Description:** Unused materials returned from site back to the store.

**Business Rules:**
- BR-F5-01: Material return must reference the original Material Requisition (MR).
- BR-F5-02: Return quantity cannot exceed the original issued quantity from that MR.
- BR-F5-03: Returned materials are inspected by the Storekeeper: condition is recorded (Reusable / Damaged / Waste).
- BR-F5-04: Reusable materials are added back to available stock and a reversal cost transaction is posted.
- BR-F5-05: Damaged or waste materials are written off — a write-off record is created (requires Store Supervisor approval).
- BR-F5-06: Only materials from the same project can be returned to the project store.

---

### F6: Inter-Store Transfer
**Description:** Movement of stock between stores within the same project, or between projects (inter-project transfer).

**Business Rules:**
- BR-F6-01: Intra-project transfer (between stores in the same project) requires Store Supervisor approval.
- BR-F6-02: Inter-project transfer (between two different projects) requires Store Supervisor approval from both the source and the destination project.
- BR-F6-03: Transfer reduces the source store balance and creates a pending receipt at the destination store. The destination Storekeeper must confirm physical receipt to complete the transfer.
- BR-F6-04: If the destination does not confirm receipt within a configurable SLA period, the system escalates to the Store Supervisor.
- BR-F6-05: Cost adjustments are posted to both projects' cost centres when an inter-project transfer is confirmed.

---

### F7: Material Return to Supplier
**Description:** Defective or excess materials returned to the supplier.

**Business Rules:**
- BR-F7-01: Return to supplier must reference the original GRN.
- BR-F7-02: Reason for return is mandatory: Defective, Over-delivery, Wrong Item, QAQC Rejection.
- BR-F7-03: Return-to-supplier reduces inventory stock and triggers a credit note request in the Procurement/Accounting module.
- BR-F7-04: Physical return must be confirmed with a Delivery Return Note (DRN) document uploaded to the system.

---

### F8: Stock Adjustment
**Description:** Corrections to stock balance due to counting errors, damage discovery, or expiry.

**Business Rules:**
- BR-F8-01: Stock adjustments can be positive (increase) or negative (decrease).
- BR-F8-02: All adjustments require a reason code: Damage, Expiry, Counting Error, Theft/Loss, Correction.
- BR-F8-03: Every adjustment requires Store Supervisor approval.
- BR-F8-04: Adjustments post to the Cost Control module — increases post a cost; decreases post a reversal.
- BR-F8-05: Adjustments are recorded in the audit log with the approver's name, reason, and before/after quantities.

---

### F9: Physical Stock Take (Cycle Count)
**Description:** Periodic physical counting of all stock to reconcile system balance against physical reality.

**Business Rules:**
- BR-F9-01: A stock take can be initiated by the Store Supervisor for one store at a time.
- BR-F9-02: When a stock take is initiated, the store is locked — no new movements (issues, receipts, transfers) are permitted until the stock take is completed or cancelled.
- BR-F9-03: The system generates a count sheet (list of all items with system quantity — quantity field is blank for the counter to fill in).
- BR-F9-04: Counted quantities are entered into the system. The system calculates variance (physical − system).
- BR-F9-05: Variances within a configurable tolerance (e.g., ±0.5% by value) are auto-approved. Variances exceeding tolerance require Store Supervisor approval before posting.
- BR-F9-06: After approval, system balances are updated via stock adjustments with reason = Stock Take Reconciliation.
- BR-F9-07: Stock take history is retained permanently and cannot be deleted.

---

### F10: Minimum Stock Alert & Reorder
**Description:** Automated alerts when stock falls below reorder point, with optional automatic PR generation.

**Business Rules:**
- BR-F10-01: When available stock for an item in a store falls at or below the item's reorder point, the system creates a Low Stock Alert and notifies the Storekeeper and Procurement Officer.
- BR-F10-02: The alert links to the item's last purchase history to help with reorder quantity estimation.
- BR-F10-03: If configured, the system can auto-generate a draft Purchase Requisition (PR) for the reorder quantity (requires Procurement module integration). The auto-generated PR is a draft — it does not submit automatically.
- BR-F10-04: Alerts are dismissed automatically when stock is replenished above the reorder point.

## 2. Status Model

### GRN Status

| Status | Description | Allowed transitions to |
|---|---|---|
| Draft | Being created by Storekeeper | Confirmed, Cancelled |
| Confirmed | GRN submitted and stock updated | (terminal — corrections via Credit GRN) |
| Cancelled | Voided before confirmation | (terminal) |

### Material Requisition (MR) Status

| Status | Description | Allowed transitions to |
|---|---|---|
| Draft | Raised by Site Engineer, not yet submitted | Submitted, Cancelled |
| Submitted | Awaiting approval | Approved, Rejected, Cancelled |
| Approved | Approved, awaiting Storekeeper to issue | Issued, Partially Issued, Cancelled |
| Issued | Fully issued | (terminal) |
| Partially Issued | Some items issued, some pending | Issued, Cancelled |
| Rejected | Rejected by approver | (terminal) |
| Cancelled | Cancelled before fulfilment | (terminal) |

### Stock Item Status (per batch/lot in store)

| Status | Description |
|---|---|
| Available | In stock, can be issued |
| Under Inspection | Received, pending QAQC inspection |
| Reserved | Reserved for an approved MR but not yet physically issued |
| Quarantined | Held due to quality concern (post-inspection hold) |
| Written Off | Damaged, expired, or lost — zero value remaining |

### Transfer Status

| Status | Description | Allowed transitions to |
|---|---|---|
| Pending | Transfer raised, awaiting approval | Approved, Rejected |
| Approved | Approved, awaiting destination confirmation | In Transit, Cancelled |
| In Transit | Source stock deducted, destination receipt pending | Received, Discrepancy |
| Received | Destination confirmed receipt | (terminal) |
| Discrepancy | Destination received different quantity | Resolved |
| Rejected | Transfer rejected | (terminal) |

## 3. Workflow Summary

```
GRN Workflow:
  Storekeeper creates GRN from PO delivery
  → [If inspection required] → QAQC quarantine → QAQC Approve/Reject
  → Stock updated (Available or Rejected)
  → Cost commitment posted

Material Issue Workflow:
  Site Engineer raises MR (linked to WBS + Task + Cost Code)
  → Site Supervisor approves
  → Storekeeper issues materials physically
  → Storekeeper confirms issue in system
  → Stock reduced + cost transaction posted

Material Return Workflow:
  Site Engineer initiates return (references original MR)
  → Storekeeper inspects condition
  → Reusable: stock added back + reversal cost
  → Damaged/Waste: write-off raised (requires Store Supervisor approval)

Inter-Project Transfer:
  Store Supervisor A requests transfer
  → Store Supervisor B approves
  → Stock deducted from source
  → Destination Storekeeper confirms receipt
  → Cost adjustments posted both sides

Physical Stock Take:
  Store Supervisor initiates stock take → store locked
  → Count sheet printed/downloaded
  → Counted quantities entered
  → System calculates variances
  → Store Supervisor approves variances
  → Adjustments posted → store unlocked
```

## 4. Integration Points

| Integrated module | Integration direction | How |
|---|---|---|
| Procurement (PRC) | PRC → INV | GRN created from approved PO; supplier delivery triggers stock receipt |
| WBS (WBS) | INV uses WBS | Every issue references a WBS node |
| Task (TSK) | INV uses TSK | Issue references active tasks |
| Cost Control (COST) | INV → COST | Every movement posts cost transaction (debit/credit by cost code) |
| BOQ (BOQ) | BOQ → INV | Material budget codes and unit rates populate item master defaults |
| QAQC (QAQC) | INV → QAQC | Incoming inspection request raised when GRN has inspection flag |
| Notification (NTF) | INV → NTF | Low-stock alerts, pending approvals, overdue transfers |
| Audit Log (AUD) | INV → AUD | All movements and approvals logged |
| Reporting (RPT) | INV → RPT | Stock balances, consumption, aging, cost reports |

## 5. Assumptions & Constraints

- **Single currency per project:** Multi-currency support is Phase 4 (FX module). For Phase 3, all inventory costs are in project's base currency.
- **FIFO costing:** Stock is valued using FIFO (First In, First Out) by default. Weighted Average Cost is a Phase 4 option. [TBD — human to confirm preferred costing method per client type]
- **No barcode scanning:** Phase 3 uses manual entry. Barcode/RFID integration is Phase 4.
- **Material test certificates:** Stored as file attachments on GRN; QAQC module manages the test record itself.
- **Negative stock:** System blocks negative stock. Backdated entries that would create negative stock are rejected.
