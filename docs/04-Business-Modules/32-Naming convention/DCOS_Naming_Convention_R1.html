01

Project Code & Name

Each project in DCOS is assigned a unique Project Code at the time of project creation. The Project Code is the root identifier for all documents, drawings, WBS nodes, and records within that project. It must remain consistent across all departments throughout the project lifecycle.

1.1 · Project Code Format
Format
P[NNN]-[Short Name] P = Fixed prefix: Project (always uppercase) NNN = 3-digit sequential number, zero-padded (001, 002 …) Short = Abbreviated project name, max 6 characters, no spaces
ComponentDescriptionExampleRemarks
PFixed prefix — ProjectPAlways uppercase
NNN3-digit sequential number001Zero-padded; assigned by Company Admin
Short NameAbbreviated project nameHTBTMax 6 chars; approved by PM before setup
1.2 · Project Code Examples
Project CodeProject Full NameShort NameNotes
P001-HTBTHattha Bank TowerHTBTPhnom Penh CBD, 30 floors
P002-CVILAChroy Changvar VillasCVILAResidential, 52 units
P003-BMALLBorey Peng Huoth MallBMALLCommercial, mixed-use

Note
The Project Code is configured by Company Admin in DCOS at project creation and cannot be changed after the first document is registered. The Short Name must be approved by the Project Manager before system setup.
02

Building Code & Name

All buildings, structures, and external works within a project must be assigned a Building Code. It is the second tier of the WBS hierarchy and is used in all document numbering, drawing references, inspection records, and cost allocations.

2.1 · Building Code Format
Format
B[A–Z] — [Building Name] Examples: BA = Building A (Tower) BB = Building B (Podium) Reserved: BX = External Works BY = Landscape BZ = Permanent Boundary
CodeBuilding / Area TypeRemarks
BABuilding A — Primary TowerFirst building in project
BBBuilding B — Secondary StructureSecond building
BCBuilding C — Podium / RetailThird building or podium block
BDBuilding D — Service BlockAncillary / service building
…Continue alphabeticallySkip I and O (risk of confusion with 1 and 0)
BXExternal WorksSite drainage, roadworks, boundary — Reserved
BYLandscapeHard and soft landscaping — Reserved
BZPermanent Boundary WorksFencing, walls, gates — Reserved
Note
Skip letters I and O in building codes to avoid confusion with numbers 1 and 0 in printed documents and drawings.
03

Level Code & Name

The Level Code is the third WBS tier. It provides a sortable, structured identifier for every floor or level within a building — including basements, ground floor, typical floors, roof, mezzanines, and non-applicable levels. The Level Code combines Building Code + Sequence Number + Level Type Prefix.

3.1 · Level Code Format
Format
[Building Code]-[Seq No.]-[Level Type][Level No.] Building Code = BA, BB, BC … (Section 2) Seq No. = 01, 02, 03 … numbered from deepest to highest (sort key) Level Type = B (Basement) G (Ground) L (Level) M (Mezzanine) R (Roof) PH (Penthouse) Level No. = 01–99 or 00 for ground/roof
3.2 · Level Type Prefixes

Note
The Sequence Number (01, 02, 03…) is critical for digital sorting. Always number from the lowest physical level upward. Do not use the level designation alone (B01, G00) as the sort key — the sequence number ensures consistent ordering across all buildings regardless of basement depth.
04

Zone Code & Name

Zone Codes subdivide a floor or level into functional areas for design coordination, construction sequencing, QA/QC inspection control, and progress reporting. DCOS maintains two separate zone systems: Design Zones (DZone) and Construction Zones (CZone).

4.1 · Design Zone Code (DZone)

Defined by the Architecture team during design development to organise finishes, MEP coordination, and design deliverables by functional area.

Zone CodeZone NameTypical ContentNotes
DZone1Wet / Service ZoneToilets, AHU rooms, electrical rooms, shaftsCommon across all floors — defined once
DZone2Core / Circulation ZoneLifts, staircases, lobbies, corridorsApplies to all floors
DZone3Primary Functional Zone ABanking hall, main office, retail areaFloor-specific — defined per floor
DZone4Primary Functional Zone BBack-of-house, storage, secondary officesFloor-specific — defined per floor
DAllAll ZonesApplies to entire floor without subdivisionUse when item is floor-wide
DZZApplies to Some FloorsSelected zones only — varies by floorDetail in schedule notes
DXXNot ApplicableZone does not exist on this floorScheduling matrix only
Note
Design Zones are used in finish schedules and material approval records. They must not appear in construction drawing titles or construction document codes. Construction zoning is managed separately via CZone.
4.2 · Construction Zone Code (CZone)

Established by the Project Manager and Site Team at the start of construction, reflecting sequencing, crane radius, subcontractor work fronts, and structural pour sequences.

Zone CodeZone NameTypical UseDefined By
CZone1Construction Zone 1First concrete pour sequence / work frontPM + Site Engineer
CZone2Construction Zone 2Second work front or crane zonePM + Site Engineer
CZone3Construction Zone 3Third zone — finishing or MEP installationPM + Site Engineer
CAllAll Construction ZonesFloor-wide construction activityPM
05

Room Code & Name

Room Codes identify individual spaces within a floor for QA/QC inspection tracking, finish schedule assignment, room data sheets, and MEP equipment placement. Every room with a defined boundary, function, or finish specification must have a unique Room Code within its floor.

5.1 · Specific Room Code (Single Floor)
Format
[Building Code].[Seq No.].[Level Code]-R[NNN] BA.04.G00-R001 → Building A, Ground Floor, Room 001 (Banking Hall) BA.04.G00-R002 → Building A, Ground Floor, Room 002 (ATM Lobby) BA.05.L01-R001 → Building A, Level 1, Room 001 (VIP Banking Suite) BA.05.L01-R015 → Building A, Level 1, Room 015 (Server Room)
ComponentDescriptionExampleNotes
BABuilding CodeBAAs defined in Section 2
04Sequence Number04From Level Code sequence — Section 3
G00Level Type CodeG00From Section 3 level table
R001Room NumberR001 → R999Sequential within floor, 3-digit zero-padded
5.2 · Typical Room Code (Multiple Floors)

When a room type is identical across multiple floors (toilet core, standard office module), a Typical Room Code is used to avoid duplicating room data sheets.

Format — Typical Room
[Building Code].00.ZZ-TR[NNN] BA.00.ZZ-TR001 → Male / Female Toilet Core (all floors L01–L30) BA.00.ZZ-TR002 → Lift Lobby (all floors G00–L30) BA.00.ZZ-TR003 → Standard Office Module (L03–L25, typical office floors) BA.00.ZZ-TR004 → Electrical Risers & Shaft (B01–R00, all floors)
Note
Typical Room Codes must be documented with the applicable floor range. When a typical room is modified on a specific floor, assign a specific R-type code for that floor and annotate the deviation from the typical layout.

Transmittal Code

Document transmittals are formal records of document issue between parties. Every transmittal in DCOS has a unique code identifying the project, issuing company, receiving company, and a sequential running number.

Transmittal Format
[Project Code]-DT-[Issuing Company]-[Receiving Company]-[NNN] P001-HTBT-DT-CMED-GGD-001 → First transmittal from CMED to GGD on Project HTBT P001-HTBT-DT-CMED-GGD-002 → Second transmittal from CMED to GGD P001-HTBT-DT-CMED-ARC-001 → First transmittal from CMED to Architect
SegmentExampleDescriptionNotes
Project CodeP001-HTBTProject identifierFrom Section 1
DTDTFixed: Document TransmittalAlways uppercase, always DT
Issuing CompanyCMEDCompany sending the transmittalMax 4 letters, uppercase
Receiving CompanyGGDCompany receiving the transmittalAgreed abbreviation per stakeholder setup
Running No.001Sequential transmittal number3-digit, zero-padded, resets per project
Note
All external documents — drawings, reports, letters, submittals, and payment certificates — must be transmitted via a registered DCOS transmittal. Documents shared informally without a transmittal are not considered officially issued and carry no revision or approval status.
